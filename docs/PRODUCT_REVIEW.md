# סקירה: הפיכת ארנו-נט למוצר לעיריות

מה צריך לשנות כדי שהתקנה לעיר חדשה תהיה כמה פעולות פשוטות ולא עבודת פיתוח.
מסודר לפי עדיפות.

---

## 0. דחוף, לפני כל השאר: מידע אישי בריפו ציבורי

הריפו ציבורי, ונמצאים בו:

- `reports/*.xlsx`: עמודת **"שמות בעלי נכסים"**, כלומר שמות של אנשים פרטיים שמחוברים לכתובות ולחשד לאי-תשלום ארנונה.
- `scripts/data/*.xlsx`, `public/arnona_lookup.json`: נתונים מקובץ נכסי הארנונה של העירייה.

זה מידע של עיריית ירושלים, וחלקו מידע אישי שחל עליו חוק הגנת הפרטיות. **גם אם לא יקום שום מוצר**, צריך:
1. להפוך את הריפו ל-**Private**.
2. להסיר את הקבצים מכל ההיסטוריה של git (`git filter-repo`), כי מחיקה רגילה משאירה אותם בהיסטוריה.
3. להוסיף את התיקיות האלה ל-`.gitignore`.

את זה לא ביצעתי, כי זו פעולה בלתי הפיכה על הריפו שלך וההחלטה צריכה להיות שלך.

## 2. חוסם להתקנה: הסכמה של מסד הנתונים לא נמצאת בריפו

בריפו יש מיגרציה אחת בלבד (`business_types`). הטבלאות `businesses`, `upload_sessions` ו-`address_locations`,
ה-trigger שמגן על מיקומים ידניים וה-RLS נוצרו ידנית ב-Supabase ואינן בקוד.
בלי זה אי אפשר להקים עירייה חדשה.

**מה צריך ממך:** להוציא את הסכמה מהפרויקט הקיים, למשל:
```bash
npx supabase db dump --db-url "<connection string>" --schema public -f supabase/migrations/00000000_base_schema.sql
```
(או מ-Dashboard → Database → Backups). אחרי זה אסדר אותה כמיגרציה בסיסית נקייה, בלי נתונים.

## 4. ארכיטקטורה: התקנה נפרדת לכל עירייה

ההמלצה היא **התקנה נפרדת לכל עירייה** (ריפו, Supabase ואתר משלה) ולא מערכת אחת לכל העיריות:
- אין סיכון שעירייה אחת תראה נתונים של עירייה אחרת.
- כל עירייה יכולה לבחור איפה הנתונים שלה נשמרים.
- זה תואם את הקוד הקיים, בלי שכתוב.

מערכת אחת לכל העיריות (multi-tenant) תהיה רלוונטית רק כשיהיו הרבה לקוחות.
